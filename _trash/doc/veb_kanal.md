- **Веб-эндпоинты для торговли из v1:** `spot/order/place`, `order/cancel/v2`, `order/deal/detail`, `current/orders/v2`, `history/orders/v2`, баланс `assetbussiness/asset/spot/statistic/v2`. Снятые запросы лежат в `запрос*.json`.

### 19.10 — решение: веб-канал для листингов с закрытым API (вариант B)
- В v1 ордер через сайт — это `POST https://www.mexc.com/api/platform/spot/order/place` с зашифрованными полями `p0`/`k0` (разные в каждом запросе) и `chash`/`mhash`/`mtoken`. Их собирает защитный JS сайта, поэтому повторить их чистыми HTTP-запросами нельзя. v1 обходил это заполнением формы в браузере.
- Выбран **вариант B**: Playwright с залогиненной сессией на странице пары вызывает функцию сайта, которая сама собирает и отправляет ордер, без заполнения формы. Официальный API остаётся основным каналом, веб-канал включается, только если пара закрыта для API. Подробности и риски — выше, раздел из resheniya_po_voprosam.md.

### 20.10 — разведка веб-API (этап 1)
Ручной LIMIT BUY 1.2 MX по 1.74 на MX_USDT с отменой, запросы перехвачены в Chrome. Сайт: Next.js на Turbopack, сборка `mxc-web-spot-v4/106`.
- **Ордер:** `POST /api/platform/spot/order/place`. Тело — обычный JSON: `currencyId`, `marketCurrencyId`, `tradeType` (BUY/SELL), `price`, `quantity`, `orderType` (`LIMIT_ORDER`), `orderSource: "WEB"`. Ответ `{"code":200,"data":"C02__741140155158421504003"}` (id ордера), около 500 мс из Киева.
- **`p0`/`k0`/`?mh=` сейчас не отправляются.** Их добавляет `window.fp.getFpDataSync()` при `needDolos: 27`, а `window.fp` на странице нет. Защита из v1 сейчас фактически не используется.
- **Подпись — заголовки `x-mxc-nonce` и `x-mxc-sign`:**
  - nonce = `Date.now()` + сдвиг времени сервера (`/api/common/ping`);
  - key = `md5(token + nonce).substring(7)`, где token — cookie `u_id`;
  - sign = `md5(nonce + queryToString(body) + key)`; `queryToString` — параметры, отсортированные по ключу.
  - Ещё заголовки: `content-type: application/json`, `platform`, `language`.
- **Отмена:** `DELETE /api/platform/spot/order/cancel/v2?orderId=…`, без подписи.
- **MARKET:** другой URL, `/api/platform/spot/v4/order/place` (`orderType: "MARKET_ORDER"`). Ещё есть `.../place/trigger/v2` и `.../v4/order/place/oco`.
- **Код сайта:**
  - общая обёртка запросов — модуль `798942`, экспорт `request` (чанк `21jb9_jcbjxdo.js`);
  - ордер ставит обработчик формы (чанк `2ww0fzbqsvy0j.js`) вызовом `request(url, {method:"POST", headers:{content-type, platform}, body:{…, orderSource:"WEB"}, needDolos:27})`.
- **Доступ из `page.evaluate` работает.** В `TURBOPACK` пушится свой модуль и запускается как runtime-модуль; он получает контекст рантайма, а `ctx.c` — это кэш модулей. Дальше `ctx.c[798942].exports.request`: тот же путь, что у кнопки, подпись и сдвиг времени сайт делает сам. Номер модуля меняется при пересборке, поэтому в боте искать его по коду (строка `x-mxc-nonce`/`withSignature`).
- **Проверено вызовом из скрипта** (с подтверждения пользователя): `request('/api/platform/spot/order/place', {…})` поставил LIMIT BUY 1.2 MX по 1.74 (`code 200`, id `C02__741142048341434368003`) за 452 мс, отмена через `request('/api/platform/spot/order/cancel/v2?orderId=…', {method:'DELETE'})` — 369 мс (из Киева). Заголовки те же, что у кнопки (`x-mxc-nonce`, `x-mxc-sign`). Открытых ордеров после теста нет.
- **MARKET через веб — работает** (MX_USDT, сделки запускал пользователь из консоли Chrome тем же вызовом `request`, проверка — официальным API):
  - URL `POST /api/platform/spot/v4/order/place`, тело `{currencyId, marketCurrencyId, tradeType, price, orderType:"MARKET_ORDER", amount | quantity, orderSource:"WEB"}`; `amount` — сумма в USDT, `quantity` — в монете. В форме сайта `price` — текущая цена (`newPrice`).
  - BUY `amount: "5"` → FILLED 2.58 MX по 1.9367 на 4.9967 USDT, ответ 452 мс. SELL `quantity: "2.58"` → FILLED по 1.9361 на 4.9951 USDT, 489 мс.
  - Биржа ставит ордеру предельную цену `price × 1.05` для BUY и `price × 0.95` для SELL (2.0309 и 1.8398). Значит, переданный `price` — защита от проскальзывания на ±5 %; для листинга передавать свежий ask/bid, иначе MARKET исполнится не дальше 5 % от него (нужно проверить, что при этом бывает — частичное исполнение или отказ).
  - Комиссия в обе стороны — 0.05 % **в USDT** (при покупке на сумму комиссия берётся с USDT, а не монетой). Итог круга −0.0065 USDT (комиссии 0.005 + движение цены).
  - Веб-ордера видны в официальном API (`/api/v3/order`, `/api/v3/myTrades`) по тому же id `C02__…`.
- **Модуль `tools/web_channel.py`** (Playwright, локальный `.venv`, профиль сессии в `.browser/mexc`, в git не попадает):
  - `WebChannel`: `start()`, `place_limit()`, `place_market()`, `cancel()`, `balance()`, `is_logged_in()`, `symbol()`. Данные пары (`cd`/`mcd`, точность `ps`/`qs`, время открытия `ot`) берутся из `/api/platform/spot/market-v2/web/symbolsV2`.
  - `request` ищется по коду: модуль кнопки ордера (в коде есть `order/place` и `needDolos`) → импорт, через который он вызывает `request`. На сайте две версии `request`: `798942` у кнопки и более старая `384399` в общей библиотеке. Запасной путь — самая полная из найденных в кэше.
  - Команды: `login` (окно для входа, логин и 2FA вводит человек), `check SYMBOL` (без ордеров), `limit-test SYMBOL` (реальный LIMIT ниже рынка и отмена; запускает пользователь).
  - Сессия перенесена из Chrome пользователя: экспорт cookies (Cookie-Editor) → `import-cookies` (файл удаляется). `limit-test MXUSDT` с ПК (запускал пользователь): LIMIT BUY 1.14 MX по 1.7424 → CANCELED, executedQty 0, открытых ордеров нет — модуль работает целиком.
  - Самопроверка в чистом профиле: Akamai пропустил Chromium из Playwright (окно, не headless), `request` найден за 3.3 с, без логина баланс отвечает `401 User not log in`.
- **Память на сервере (1 ГБ).** Тариф Lightsail на 2 ГБ ($12) аккаунту недоступен: при создании из снимка `mexc-tokyo-1-1792487077` ответ `CreateInstancesFromSnapshot … can not create an instance using this Lightsail plan size` — снимать ограничение через поддержку AWS. Снимок оставлен.
  - На сервере сделано: swap-файл 2 ГБ (`/swapfile`, в `/etc/fstab`), `vm.swappiness=10`; в venv поставлены Playwright 1.64 и Chromium, системные библиотеки и Xvfb (`playwright install-deps`).
  - Замер Chromium на странице MX_USDT (60 с, Linux): без окна — PSS 425–500 МБ, свободная память падает на 365–413 МБ; с окном под Xvfb — на 400–450 МБ. Облегчённая страница (без графика, картинок, шрифтов, аналитики) экономит лишь 30–50 МБ.
  - До браузера свободно ~566 МБ; с браузером остаётся ~120–150 МБ, на листинге проба и запись рынка уйдут в swap. Работать можно, но для боевого режима нужен сервер на 2 ГБ.
  - Задержка веб-API из Токио (keep-alive, вызов через `request` в странице): публичный тикер — медиана 50 мс (мин. 38), запрос баланса — 78 мс; новое соединение ~120 мс до первого байта. Официальный API отсюда ~20 мс.

### 20.10 — MPLX: тикер сайта, сессия на сервере, облегчённый режим
- Время открытия есть в публичном тикере сайта без логина: `GET https://www.mexc.com/api/platform/spot/market-v2/web/symbol/ticker?symbol=MPLX_USDT` → `data.ot` (curl с сервера проходит).
- **Сессия на сервере:** cookies из Chrome загружены (`import-cookies`), `check` — залогинен. Но запросы шли 3–8 с: пока открыта торговая страница, CPU сервера занят ~70 % (стакан, график, лента). На прогретой странице тикер ~50 мс, баланс — медиана 90 мс, но всплески до 0,4–2,7 с. Нужна страница без рыночных обновлений (блокировать WS страницы и график) — иначе и задержка нестабильна, и CPU-кредиты тарифа $7 сгорят.
- **Облегчённый режим `web_channel` (по умолчанию; `--full` — полная страница, `login` всегда полный).** Блокируются график TradingView, аналитика, push-SDK, капча, картинки, шрифты (перехват только по адресу — запросы API идут мимо Python); WebSocket страницы подменяются пустышкой; поверх торговой вкладки открывается пустая, чтобы браузер её не перерисовывал. Замер на сервере (60 с, залогинен, 25 пар запросов):

  | Режим | CPU в среднем (макс.) | Тикер: медиана / p90 / макс | Баланс: медиана / p90 / макс |
  |---|---|---|---|
  | Полная страница | 81 % (91 %) | 167 / 466 / 2165 мс | 175 / 476 / 1482 мс |
  | Без графика и WS | 69 % (88 %) | 92 / 165 / 256 мс | 161 / 244 / 769 мс |
  | + торговая вкладка в фоне | **16 %** (46 %) | **65 / 148 / 169 мс** | **143 / 194 / 674 мс** |

  Первые секунды после запуска страница догружается и запросы идут 1,5–3 с, поэтому `limit-test` сначала прогревает страницу (`--warmup`, 20 с). Боевой веб-канал должен стартовать заранее, а не в момент листинга.

### 22.10 — потолок цены в веб-API
- **В веб-API потолка нет.** Форма сайта берёт данные пары из `GET /api/platform/spot/market-v2/web/symbol/trade?symbol=X_USDT` (публичный, с сервера проходит curl) и тикера `.../web/symbol/ticker`. Полный список полей — функция `assembleSymbol` в JS сайта; поля «потолок открытия» там нет. В `symbol/trade` есть: `blr`/`slr` = 0.2 (это `PERCENT_PRICE_BY_SIDE`), `mwt` = 0.05 (порог MARKET, ±5 %), `la`/`li` и `ma`/`mi` (макс./мин. сумма LIMIT и MARKET), комиссии `tfr`/`mfr` (у новых пар `tfr` = 0.0008, у MX 0.0005 — проверить по реальным сделкам).
- Форма проверяет цену только так: BUY дороже `последняя цена × (1 + blr)` → «цена вне диапазона» (`isPriceExceedRange`). Во время заморозки последняя цена = потолок, поэтому форма пропускает цены до потолок × 1.2, а отклоняет их уже биржа: `30010`, текст сайт собирает из `_extend.price` ответа.

## Заметки 20.10, которых не было в журнале
- Если у вызова `request` задан `needDolos`, обёртка вызывает `window.fp.getFpDataSync({userId: sessionStorage.mexc_session_member_id, scene: 27})` и подмешивает в тело `p0`/`k0`/`chash`/`mhash`/`mtoken`, а в URL добавляет `?mh=<mhash>`. SDK получает только userId и scene, тело ордера — нет (то есть, похоже, ордер этим не подписывается; не проверено).
- `window.fp` нет ни в статически загружаемых скриптах, ни в SDK trochilus / watchman (gotoda.co): он внедряется во время работы страницы, исходник не найден.
- `curl_cffi` с `impersonate="chrome"` получает от Akamai 200 на GET страницы и JS (обычный curl — 403). POST на `order/place` не проверялся. Сенсорные скрипты Akamai — `/akam/13/...` и обфусцированный путь ~600 КБ.
