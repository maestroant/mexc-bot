## 1. Главные выводы

1. **Официальный API на листингах работает не всегда.** Зависит от листинга (видимо, от зоны):

   | Листинг | Дата | Зона | API на старте |
   |---|---|---|---|
   | WFI/USDT (WeFi) | 06.10 13:00 | Innovation | ✅ ордер принят через 1,7 с |
   | MTO/USDT (MetaOne) | 13.10 | Innovation | — листинг перенесён MEXC за 38 мин до старта |
   | BORDR/USDT, BORDR/USD1 | 14.10 05:45 / 05:55 | Launchpad + Assessment | ❌ закрыт ~45 мин (`10007`) |
   | CHOMP/USDT | 15.10 11:00 | Innovation + MEME | ✅ ордер принят через 1,2 с от первой сделки, 19 из 19 |

2. **Серверы API MEXC включают пару не одновременно.** На BORDR с 6-й по 45-ю минуту примерно 1 ордер из 5–10 проходил, остальные получали `10007`. На MTO `status` и `apiAllowed` «мигали» несколько минут. Одному ответу API верить нельзя.
3. **Сервер нужен в Токио.** MEXC работает через CDN (Akamai для REST, AWS CloudFront для WS), сами серверы, по всей видимости, в AWS Tokyo. Из Токио запрос занимает около 20–35 мс, из Киева около 300 мс.
4. **Будущие листинги видны в `exchangeInfo` заранее** со `status=2` (обычно за сутки и более). Время старта — поле `firstOpenTime`: оно появляется вместе со `status=1` за 5–85 мин до открытия и совпадает с открытием до секунды (проверено 23.10 на 13 листингах).

  | LIMIT SELL половины на 50 % ниже bid | ❌ `30002 minimum transaction volume … 1USDT` | ❌ **`30087 Order price exceeds allowed range`** |

- **MARKET BUY и MARKET SELL через официальный API работают.** Ответ приходит за доли секунды.
- **Минимальная сумма ордера (1 USDT) считается по цене лимитного ордера.** Поэтому веб-форма критической продажи и вводит Total = 1,2 USDT.

- В пробу добавлен флаг `--market-test` (один раз на пару: MARKET BUY 5 USDT → LIMIT SELL половины на −50 % → MARKET SELL → при отказе запасной выход LIMIT по bid −2 %). Тест делается только при спреде ≤ 10 % и достаточной глубине bids. Наблюдатель запускает его на каждом листинге (служба с `--real-order --market-test`). Так проверим, работает ли MARKET и на листингах, где API в первые минуты закрыт.

## 3. Как устроено сейчас

### Сервер
- `ubuntu@52.193.127.80`, ключ `~/.ssh/mexc-tokyo`, проект в `~/mexc-bot`.
- `~/mexc-bot/.env` — ключ MEXC (`MEXC_API_KEY`, `MEXC_API_SECRET`).
- `~/mexc-bot/.venv` — Python 3.12 с `websockets`, `protobuf`, `grpcio-tools`.
- `~/mexc-bot/tools/mexc_pb/` — proto-файлы MEXC (github.com/mexcdevelop/websocket-proto), скомпилированные в Python. **В локальной копии проекта их нет.**
- Служба `mexc-listing-watcher` (`deploy/mexc-listing-watcher.service`): включена в автозагрузку, `Restart=always`. Пробы и записи запускаются отдельными процессами и переживают перезапуск службы (`KillMode=process`).

### Наблюдатель — `tools/listing_watcher.py`
- Раз в 60 с берёт полный `exchangeInfo` и передаёт его трекеру листингов (`tools/listings.py`, с 23.10).
- Трекер отслеживает пары со `status≠1` без истории сделок (будущий листинг) и пары со `status=1`, у которых `firstOpenTime` в будущем.
- Об этих парах пишет в Telegram (только USDT-пары, `--notify-quotes`): будущий листинг, время старта, перенос, снятие до старта, напоминание за 5 мин до старта (`--remind-min`; только если время объявили больше чем за 15 мин). Получатели — `TG_LISTING_CHAT_ID`, если не задан — `TG_CHAT_ID`.
- На каждую пару запускает пробу (`--open auto --duration 3600 --real-order`) и запись.
- Состояние хранится в `logs/watcher_state.json`, журнал — в `logs/watcher.log`.

### Проба API — `tools/probe_listing.py`
- Каждую секунду проверяет: `exchangeInfo` (status, apiAllowed), `defaultSymbols`, `selfSymbols`, стакан, `order/test` и реальный LIMIT BUY на 2 USDT на 10 % ниже bestBid с немедленной отменой.
- В режиме `--open auto`, пока пара закрыта, опрашивает только `exchangeInfo` раз в 10 с. T=0 — первый двусторонний стакан при `status=1`.
- Результат пишется в `logs/probe_<ПАРА>_*.jsonl`, вывод консоли — в `logs/probe_<ПАРА>_console.txt`.

### Запись рынка — `tools/listing_recorder.py`
Пишет в `logs/rec_<ПАРА>_*.jsonl.gz`, по строке на событие, с локальным временем получения:
- **WS публичные** (protobuf, декодированные): сделки (10 мс), diff-стакан (10 мс), лучшие bid/ask (10 мс), стакан 20 уровней, свеча 1m, мини-тикер;
- **WS приватные**: ордера, сделки и баланс аккаунта (через listenKey);
- **REST раз в секунду**: `exchangeInfo`, стакан 1000 уровней, последние 1000 сделок, тикер 24h, bookTicker;
- **события**: подключения, `STATUS_ONLINE`, `OPEN_DETECTED`, `DONE`.

Записывает час после открытия.
