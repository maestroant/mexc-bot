## 1. Главные выводы

1. **Официальный API на листингах работает не всегда.** Зависит от листинга (видимо, от зоны):

   | Листинг | Дата | Зона | API на старте |
   |---|---|---|---|
   | WFI/USDT (WeFi) | 06.10 13:00 | Innovation | ✅ ордер принят через 1,7 с |
   | MTO/USDT (MetaOne) | 13.10 | Innovation | — листинг перенесён MEXC за 38 мин до старта |
   | BORDR/USDT, BORDR/USD1 | 14.10 05:45 / 05:55 | Launchpad + Assessment | ❌ закрыт ~45 мин (`10007`) |
   | CHOMP/USDT | 15.10 11:00 | Innovation + MEME | ✅ ордер принят через 1,2 с от первой сделки, 19 из 19 |

2. **Серверы API MEXC включают пару не одновременно.** На BORDR с 6-й по 45-ю минуту примерно 1 ордер из 5–10 проходил, остальные получали `10007`. На MTO `status` и `apiAllowed` «мигали» несколько минут. Одному ответу API верить нельзя.
3. **Сервер нужен в Токио.** MEXC работает через CDN (Akamai для REST, AWS CloudFront для WS), сами серверы, по всей видимости, в AWS Tokyo. Из Токио запрос занимает около 20–35 мс, из Киева около 300 мс.
4. **Будущие листинги видны в `exchangeInfo` заранее** со `status=2` (обычно за сутки и более). Времени старта в API нет, оно есть только на странице пары (таймер).

### Запись рынка — `tools/listing_recorder.py`
Пишет в `logs/rec_<ПАРА>_*.jsonl.gz`, по строке на событие, с локальным временем получения:
- **WS публичные** (protobuf, декодированные): сделки (10 мс), diff-стакан (10 мс), лучшие bid/ask (10 мс), стакан 20 уровней, свеча 1m, мини-тикер;

Записывает час после открытия. В сообщениях канала свечи есть `symbolId` — внутренний id пары, который нужен веб-эндпоинтам.

### 19.10 — решение: веб-канал для листингов с закрытым API (вариант B)
- В v1 ордер через сайт — это `POST https://www.mexc.com/api/platform/spot/order/place` с зашифрованными полями `p0`/`k0` (разные в каждом запросе) и `chash`/`mhash`/`mtoken`. Их собирает защитный JS сайта, поэтому повторить их чистыми HTTP-запросами нельзя. v1 обходил это заполнением формы в браузере.
- Выбран **вариант B**: Playwright с залогиненной сессией на странице пары вызывает функцию сайта, которая сама собирает и отправляет ордер, без заполнения формы. Официальный API остаётся основным каналом, веб-канал включается, только если пара закрыта для API. Подробности и риски — в [resheniya_po_voprosam.md](resheniya_po_voprosam.md), раздел «Архитектура».
- Проект переведён в git; граф кода строит graphify (`graphify-out/`), post-commit хук перестраивает его после каждого коммита.

### 20.10 — разведка веб-API (этап 1)
Ручной LIMIT BUY 1.2 MX по 1.74 на MX_USDT с отменой, запросы перехвачены в Chrome. Сайт: Next.js на Turbopack, сборка `mxc-web-spot-v4/106`.
- **Ордер:** `POST /api/platform/spot/order/place`. Тело — обычный JSON: `currencyId`, `marketCurrencyId`, `tradeType` (BUY/SELL), `price`, `quantity`, `orderType` (`LIMIT_ORDER`), `orderSource: "WEB"`. Ответ `{"code":200,"data":"C02__741140155158421504003"}` (id ордера), около 500 мс из Киева.
- **`p0`/`k0`/`?mh=` сейчас не отправляются.** Их добавляет `window.fp.getFpDataSync()` при `needDolos: 27`, а `window.fp` на странице нет. Защита из v1 сейчас фактически не используется.
- **Подпись — заголовки `x-mxc-nonce` и `x-mxc-sign`:**
  - nonce = `Date.now()` + сдвиг времени сервера (`/api/common/ping`);
  - key = `md5(token + nonce).substring(7)`, где token — cookie `u_id`;
  - sign = `md5(nonce + queryToString(body) + key)`; `queryToString` — параметры, отсортированные по ключу.
  - Ещё заголовки: `content-type: application/json`, `platform`, `language`.
- **Отмена:** `DELETE /api/platform/spot/order/cancel/v2?orderId=…`, без подписи.
- **MARKET:** другой URL, `/api/platform/spot/v4/order/place` (`orderType: "MARKET_ORDER"`). Ещё есть `.../place/trigger/v2` и `.../v4/order/place/oco`.
- **Код сайта:**
  - общая обёртка запросов — модуль `798942`, экспорт `request` (чанк `21jb9_jcbjxdo.js`);
  - ордер ставит обработчик формы (чанк `2ww0fzbqsvy0j.js`) вызовом `request(url, {method:"POST", headers:{content-type, platform}, body:{…, orderSource:"WEB"}, needDolos:27})`.
- **Доступ из `page.evaluate` работает.** В `TURBOPACK` пушится свой модуль и запускается как runtime-модуль; он получает контекст рантайма, а `ctx.c` — это кэш модулей. Дальше `ctx.c[798942].exports.request`: тот же путь, что у кнопки, подпись и сдвиг времени сайт делает сам. Номер модуля меняется при пересборке, поэтому в боте искать его по коду (строка `x-mxc-nonce`/`withSignature`).
