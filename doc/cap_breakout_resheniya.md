# CAP BREAKOUT: решения по ТЗ v2

Вторая стратегия — торговля после снятия потолка цены на открытии листинга. ТЗ v2 от 29.10.2026: [mexc_cap_breakout_v2/MEXC_CAP_BREAKOUT_REQUIREMENTS.docx](mexc_cap_breakout_v2/MEXC_CAP_BREAKOUT_REQUIREMENTS.docx); первая версия (27.10) — [mexc_cap_breakout_download/](mexc_cap_breakout_download/). Вопросы клиенту и первый прогон — документ «CAP BREAKOUT v2: пробная заявка, стопы и первый прогон» (29.10); ответы клиента — 29.10. Все числа — стартовые значения для REPLAY, не оптимизированные; каждый прогон сравнивается с LEGACY_STOPS.

## Пробная заявка за потолком

- **Когда (§3.2, §13).** Не в `onNewListing`, а по первой сделке или в `firstOpenTime` (что раньше): до старта биржа отвечает `30001` на любой ордер. На `30001` — повтор через 200 мс, не больше 5 раз за первые 2 с; такие отказы не считаются попыткой в `maxProbeAttempts`. Остальные ответы — как в §3.2: `30010` → потолок, принят → отмена и сверка, неизвестен → ORDER_UNKNOWN.
- **Каким ордером.** `LIMIT_MAKER` BUY на 10 % выше лучшего bid (во время заморозки bid = потолок). Без заморозки биржа принимает такой ордер и сама отменяет; исполниться он может, только если ниже его цены нет продавцов и кто-то продаст ему до нашей отмены.

## Выход: профили CAP_DYNAMIC

Два независимых профиля, FAST и CONFIRMED. LEGACY_STOPS (−8 %, −6 % за 1 с, −2,5 % за 3 с, BE +1,5/+0,15 %, 3/5/8 с, удержание 15 с) — только для сравнительного REPLAY.

| Параметр | FAST | CONFIRMED |
|---|---|---|
| HARD_STOP | −6 % | −5 % |
| FAST_WINDOW_DUMP | −5 % за 1 с | −4 % за 1 с |
| FAST_DROP_STOP | −3 % за первые 3 с | −2,5 % за первые 3 с |
| BREAK_EVEN_STOP — активация / защита | +5 % / +0,5 % | +3 % / +0,3 % |
| TIME_STOP_NEGATIVE | 3 с / −0,5 % | 3 с / −0,3 % |
| TIME_STOP_NO_EDGE | 6 с / +0,5 % | 5 с / +0,3 % |
| TIME_STOP_NO_MOMENTUM | 10 с | 8 с |
| Падение bid-VWAP | −4 % за 1 с | −3 % за 1 с |
| DEPTH_DISAPPEARED | глубина ниже 5 × остатка | глубина ниже 8 × остатка |
| Trailing до TP1 — активация / откат | MFE +4 % / 3 п. п. | MFE +2,5 % / 2 п. п. |
| TP1 | +10 %, продать 50 % | +5 %, продать 50 % |
| Trailing после TP1 | 15 % от пика `exitVWAP` | 10 % от пика `exitVWAP` |
| Защита общего netPnL после TP1 (`targetFullPnLPct`) | +0,5 % | +0,3 % |
| Резерв проскальзывания (`slippageStressPct`) | 1,5 % | 1 % |
| Максимальное удержание (абсолютный предел — 120 с) | 45 с | 60 с |

**Trailing до TP1 (подтверждено клиентом 29.10).**

1. `netPnLPct` позиции — по `exitVWAP` всего доступного остатка: фактическая стоимость покупки, комиссия BUY, ожидаемая комиссия SELL и резерв проскальзывания (учитывается один раз, из уровня trailing повторно не вычитается).
2. MFE — максимум этого `netPnLPct` с момента покупки; при откате не уменьшается.
3. При MFE ≥ порога активации trailing включается и больше не выключается; выход, когда `netPnLPct ≤ MFE − откат`. FAST: MFE +4 % → выход при +1 %, +7 % → +4 %, +12 % → +9 %. CONFIRMED: +2,5 % → +0,5 %, +4 % → +2 %, +6 % → +4 %.

**Остальные правила клиента (29.10).**

- До фактического исполнения TP1 trailing контролирует всю позицию. После первого частичного исполнения TP1 — пересчёт реализованного и потенциального общего PnL, дальше остатком управляют trailing после TP1 и защита общей прибыли.
- Trailing после TP1 — от максимального `exitVWAP` остатка, а не от последней сделки.
- Из нескольких сработавших защит действует самый строгий уровень; аварийные выходы (исчезновение ликвидности, резкое падение, HARD_STOP) — всегда первыми.
- При срабатывании защиты: отменить конфликтующие TP, сверить исполнения, продать только фактический остаток.
- DEPTH_DISAPPEARED — в USDT относительно текущей стоимости остатка; обычное снижение глубины — два обновления подряд; если `exitVWAP` посчитать нельзя — сразу.
- Логировать: MFE, текущий netPnL, активный защитный уровень, причину выхода, комиссии, ожидаемое проскальзывание и фактические исполнения.
- Срабатывание trailing — начало выхода, а не гарантия цены исполнения.

**Ответы клиента 30.10** (документ «CAP BREAKOUT: первый REPLAY и три вопроса»; всё — только для REPLAY, не для LIVE):

- **DEPTH_DISAPPEARED** — глубина ниже порога непрерывно не менее 1 с (в REPLAY сравнить 0,5 / 1 / 2 с); основная полоса — 1,5 % от bestBid, полосу 0,7 % логировать. Если `exitVWAP` посчитать нельзя — выход сразу; другие аварийные стопы не задерживать.
- **Фильтр входа `entryStressLoss`** — по ожидаемому `buyVWAP` с резервом 0,5 % для обоих алгоритмов; резервы FAST 1,5 % и CONFIRMED 1 % — только для защитного выхода и trailing. Предел LIMIT BUY bestAsk +1 % сохраняется. Для сравнения в REPLAY — консервативный вариант по максимальной цене и фильтр резкого падения bid-VWAP перед BUY (отдельно проверить PRSM).
- **Временные стопы** — основной CAP_DYNAMIC без изменений; сравнительный профиль CAP_NO_TIME_STOPS без TIME_STOP_NEGATIVE / NO_EDGE / NO_MOMENTUM (HARD_STOP, аварийные, TP, trailing и maxHold остаются). Сравнивать полный PnL, максимальный убыток, MFE/MAE, время удержания, число прибыльных и убыточных сделок; отдельно проверить исполнение критических SELL, частичных TP, комиссии и округление количества.

**Наши трактовки для REPLAY (сравниваем варианты, потом подтвердить у клиента).**

- **Основа для стопов.** Trailing и защита общей прибыли считаются с резервом проскальзывания (так решил клиент). Для HARD_STOP, FAST_DROP, BREAK_EVEN и TIME_STOP_* в основном ТЗ `netPnL` был без резерва. Если считать их с резервом, сразу после входа результат уже около −(спред + 0,1 % + 1,5 %), и TIME_STOP_NEGATIVE на 3-й секунде закроет почти каждую сделку FAST без роста от ~2 %. В REPLAY — оба варианта, по умолчанию без резерва.
- **FAST_WINDOW_DUMP и «падение bid-VWAP».** Если оба считать по одной величине, то −4 % всегда срабатывает раньше −5 %, и FAST_WINDOW_DUMP никогда не нужен. Считаем FAST_WINDOW_DUMP по цене сделок за 1 с, а «падение bid-VWAP» — по `exitVWAP(Q)` за 1 с.
- **TIME_STOP_NO_EDGE / NO_MOMENTUM** — как в основном ТЗ (C1, C3): условие проверяется непрерывно с указанной секунды; NO_MOMENTUM — TP1 не исполнен и `exitVWAP` за последние 2 с не вырос.
- **BREAK_EVEN при trailing до TP1.** При тех же основах BE всегда мягче trailing (FAST: при MFE +5 % trailing выходит при +2 %, BE — при +0,5 %), поэтому на деле не срабатывает. Оставляем как задано.
